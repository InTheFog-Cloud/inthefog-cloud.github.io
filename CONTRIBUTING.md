# Contributing to InTheFog

Catalog entries and documentation must be approved for public publication. Provide
a useful summary, supported platforms, the existing maturity label, and verified
public project/documentation links. Keep customer material and internal planning
out of this repository and its build. The catalog does not import a private registry.

Delivery work and website defects are managed through the owner's private operations
process. Public Issues are disabled. Contact the owner through the existing project
channels for proposed additions.

Build and review contributions on trusted branches. Fork pull requests do not execute
on shared HCS runners; the owner reviews a contribution and brings it into a trusted
repository branch for checks before merging. Do not merge a fork PR directly with a
skipped build. Main requires passing checks and owner review.

Use the HCS Governance MCP and [AGENTS.md](AGENTS.md) for development standards.
